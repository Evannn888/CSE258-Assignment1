CSE258 Assignment 1 - write-up (v6)

General
All models use only the designated training CSV of each task. Test files are read for their queries
(user/item ids, timestamps, candidate pairs), never for labels. assignment1.py regenerates every
prediction file; validation numbers below come from held-out training data, not the leaderboard.

Facts about the data that drive the design (checked on the provided files):
(1) Tasks 2, 4, 5: the negative is the item of a randomly sampled interaction, so candidate popularity
    follows the interaction distribution exactly. Raw popularity is useless; every feature is a lift,
    and every model is trained against negatives drawn the same way.
(2) The Task 1-4 datasets are 10-cores: every item has at least 10 interactions across the training
    file and both test files (no exceptions).
(3) Timestamps are dates: every value falls between 05:00 and 10:00 UTC, so the order of events on the
    same day carries no information. Task 5/6 test rows are each user's latest interaction.

Latent factor models (Tasks 2, 4, 5)
BPR-trained models whose negatives are popularity samples: matrix factorisation with item biases; an
SVD++-style variant whose user vector adds the (normalised) sum of history item vectors; for Task 4
item-by-month biases and user-by-year factors; and an FPMC-style variant whose score adds the
similarity between the candidate and the items next to the query in the user's timeline (before and
after the query time for Task 4, the last items for Task 5). They are trained separately on every
validation fold and on all data for the test, and their scores are stacking features.

Tasks 1 and 3: rating prediction
The leaderboard skips ground-truth zero ratings, so the target is the rating given that it is
positive; zero ratings remain implicit interactions. Base feature bank: shrunk user/item biases,
explicit MF, user-block SVD++, spectral residual profiles, reliable top-K item neighbourhoods,
cumulative-logit rating styles and inferred reading stages (Task 1); Task 3 adds temporal session and
drift random effects. New in this version: the bank is computed out-of-fold for every training rating
(18 folds, each base fit leaves out 1/18), so the stacker - a Ridge anchor plus a residual gradient-
boosted tree (127 leaves, 1500 rounds) - learns from about 1.8M (Task 1) and 1.4M (Task 3) ratings
instead of 150k. Test features come from all 18 fold models and the predictions are averaged.
Validation: Task 1 0.5277 -> 0.5227 MSE on the previous version's 50k audit rows; Task 3 0.6640 ->
0.6575 on held-out out-of-fold rows. Tuned matrix factorisation and a learned neighbourhood model were
also tried; on this data they add nothing beyond the biases and neighbourhood features already used.

Tasks 2 and 4: which of two items did the user interact with
Per candidate: item-item co-occurrence evidence aggregated over the user's history (each neighbour
who shares a history item and has the candidate votes 1/(history length+2), normalised by the
popularity of both items, with rating weights); spectral features from a truncated SVD of the
degree-normalised user-item matrix; Task 2 adds the candidate's activity during the user's active
period; Task 4 weights history items by closeness to the query time, adds the candidate's popularity
in windows around the query time and a time-weighted user-based neighbourhood; plus the latent model
scores. An antisymmetric gradient-boosted classifier on feature differences and symmetric context
decides each pair; training pairs come from four held-out folds of 30k interactions with two
popularity negatives each. Two exact rules: a candidate already in the user's training history is the
negative, and an item whose training + other-test count is below 10 must be the positive in at least
that many rows (10-core deficit rule). Validation accuracy: Task 2 0.947, Task 4 0.941.

Task 5: next item in the sequence
Features: order-aware co-occurrence evidence (did neighbours take the candidate shortly after the
shared item), position statistics of items in histories, spectral features with recency weights, the
candidate's popularity in windows after the time of the user's last training event relative to all
activity in those windows, and the latent scores (MF and FPMC-style). Training sets mimic the test:
every user's last event is held out, on the full data and on data truncated at four earlier cutoffs,
with three popularity negatives each. A candidate never seen in training is always the positive; a
candidate already in the history is the negative. Validation accuracy 0.932 (train on cutoff sets,
test on last events). --task5-order-only runs the model without any timestamp.

Task 6: time until the final interaction
Pseudo-labels: drop each user's last k-1 training events (k = 1, 2, 3); the new last event is the
target and its gap from the previous event the label. Features: the user's gap distribution, the time
left until the end of the data, the target item's popularity in windows after the user's last event,
quantiles of the item's interaction times after that event, and the usual break other readers took
before reading it. An absolute-error gradient-boosted model on log(1+gap) predicts the median.
Gaps grow toward the end of a history (training one step earlier and testing one step later shows
systematic under-prediction), so predictions are scaled by 1.10 and capped by the time left.
Validation MAE on last-training-event targets: 7.1M seconds.
